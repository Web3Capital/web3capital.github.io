从发现与交付，到验证、价值状态与开放构建，每种动作都有自己的事实边界、责任主体与授权条件。

  1. SERVICE METHOD ACTIVE · COMPONENT READINESS SEPARATE

    理解意图，发现可信候选。

    当前服务方法连接需求、信息、能力、服务与智能体；具体技术组件的可用性单独登记，匹配结果只是可解释建议。

    边界不是认证、排名或交易成立。
  2. ACTIVE BY SCOPED ENGAGEMENT

    让承诺、工作与验收进入同一任务链。

    正式服务运营通过具名范围、责任、里程碑、交付、证据与验收连接工作；底层组件可用性单独登记。

    边界不表示在线自助下单或自动执行已经开放。
  3. DELIVERY METHOD ACTIVE · COMPONENT READINESS SEPARATE

    让声明和证据具有上下文。

    当前交付验证方法连接主张、证据、验证状态、更正、撤销与争议；不表示 PROOF 或 GRAPH 技术组件已经上线。

    边界实证不等于绝对真实或质量认证。
  4. NOT AUTHORIZED

    连接价值状态，不越权持有资金。

    PAY 计划连接报价、发票、授权、外部伙伴资金状态、退款与对账。

    边界当前没有真实资金、托管或结算服务。
  5. NOT REGISTERED

    通过开放对象接入网络。

    DEVELOPER 与 PROTOCOL 计划通过规范、API、SDK、签名导出与沙箱连接应用和智能体。

    边界当前没有生产 API、SDK 或开发者账户。

事实由最接近它的权威域写入。

身份、工作、验证与价值状态各有写入者。任何模型、页面或绿色测试都不能静默提升另一条状态。

NOT REGISTERED

身份与授权

设计为记录人、组织与智能体的身份、能力声明和授权事实；技术身份不自动等于法定身份。

NOT REGISTERED

任务与验收

设计为记录任务规格、承诺、里程碑、交付、证据和验收事实；其他组件不得静默补写。

NOT REGISTERED

声明与验证

设计为记录主张、证据、验证状态、更正和撤销，不保证现实内容绝对真实。

NOT AUTHORIZED

价值状态

计划记录报价、发票、外部资金状态、退款与对账；真实资金只能由未来合格伙伴处理。

关键状态不能由一个模型决定。

OPERATING PRINCIPLE

TRUST

设计为解释公开规则、状态语义、利益冲突、验证边界、争议、更正和撤销。

NOT REGISTERED

管理 / 运营

计划承担受控执行、事故处理、暂停、恢复与运营责任，但不能静默改变业务事实。

DESIGN RULE

人工决策点

高影响授权、验收、资金、公开实证、公共锚定和治理变更必须停在具名责任人面前。

DESIGN RULE

追加式历史

更正、撤销、争议和裁决追加新状态，不把过去无痕覆盖。
